## Как ведём гипотезы (GitHub Issues)

- Одна гипотеза = один issue. Заголовок: `H-### · утверждение`.
- Статус = состояние issue + лейбл:
  - open + `status-idea` — идея;
  - open + `status-ready` — готова к проверке;
  - open + `status-running` — в работе;
  - open + `status-parked` — отложена;
  - closed + `status-confirmed` / `status-refuted` — итог.
- Новый issue заводим с телом: утверждение, почему, как проверяем, критерий.
- **Порог успеха фиксируется до прогона.**
- Один прогон — одно изменение.
- Закрывая issue, пишем комментарий: `E-###`, что меняли, CV, Δ, ссылка на W&B,
  вердикт. Затем закрываем.
- Опровергнутые не удаляем.
- Не больше 3 гипотез в `status-running`.
- Прогоны без гипотезы (диагностика) — отдельные issue с лейблом `experiment`.

## Факты о данных (проверено)

- `train.csv`: 2 699 строк = 150 промптов × 18 моделей. В каждом промпте по
  одному ответу от каждой модели (`claude-fable-5` — 149, одной генерации нет).
- `test.csv` локально: **3 строки** (заглушка). В ререне ~4 000 пассажей.
- **Тестовые промпты не пересекаются с train** (явно в Data description).
  Сплит по промптам → валидация только GroupKFold по `prompt_id`.
- Длина: 36–274 слова. Разброс внутри промпта ≈ общий (std 56.8 vs 58.3),
  т.е. длину задаёт генерация, а не промпт. Остаточные средние по моделям:
  от −14 (gemini-3.8-flash) до +9 (claude-opus-4-8) слов при σ≈57 → сигнал
  слабый, но не нулевой.
- Форматирование чистили (снимали `**bold**`), авторская типографика осталась.
- 18 классов: 5×OpenAI, 4×Google, 5×Anthropic, 1×Qwen, 2×ZAI, 1×Moonshot.

## Метрика и валидация

Balanced accuracy по 18 классам: среднее per-class recall. Классы в тесте
неравномерны, public/private = 40/60. Следствия:
- веса классов при обучении (`auto_class_weights='Balanced'` / `class_weight`);
- на инференсе коррекция приоров: `argmax p(y|x)/p(y)`;
- выбирать модель по BA, не по accuracy.

Протокол (утверждён):
- **Repeated GroupKFold по `prompt_id`** (5 фолдов × 5–10 повторов);
  метрика считается по **объединённым OOF**, а не средним по фолдам.
- LOPO — эталон для дешёвых моделей.
- Дисперсия: кластерный bootstrap по 150 промптам (B=2000). **SE(BA) ≈ 0.020.**
- Приём идеи: Δ ≥ **0.015**, CI разности не содержит 0, знак стабилен в ≥4/5.
- Optuna: одинаковые сиды и сплиты во всех триалах (парные сравнения),
  pruning по повторам (2→5→10), выбор по mean, one-SE rule к регуляризации.

## Ключевая переформулировка

В train каждый промпт даёт ровно один ответ каждой модели. Значит:

1. BA = **среднее по промптам от s_p** (доля верных из 18 внутри промпта).
   Единица анализа — промпт, n=150. Отсюда CI и парные тесты по промптам.
2. **Тема не утекает при GroupKFold**: внутри промпта все 18 классов на одной
   теме, группировка её вырезает. Наш CV — честная оценка новых промптов.
3. «0.307 CV vs 0.669 LB» — **не загадка и не разрыв**: 0.669 — чужие сильные
   модели. Сравнивать CV с LB напрямую нельзя, пока нет своего сабмита.
4. Тест: ~4000 ≈ 222×18, но ровно на 18 не делится, и пассажей на модель
   не равно. Жёсткий Hungarian неверен — нужны мягкие маржиналы/ёмкости.
5. **Блочную логику можно валидировать на train**: held-out промпт = блок
   из 18 текстов, внутри решаем назначение. Офлайн-аналог теста.

## Логирование

- **W&B (cloud, free tier)** — основной трекер: графики, сравнение ранов,
  скриншоты. На Kaggle — `WANDB_MODE=disabled`.
- **Optuna + SQLite + optuna-dashboard** — HPO (`runs/optuna.db`).
- Локальный JSONL-реестр (`runs/`) — fallback и воспроизводимость.
- Всё под флагом: импорт W&B не должен ломать инференс без интернета.

## Инфраструктура и правила

- Mac (darwin/arm64): CatBoost + Optuna локально; torch MPS для эмбеддингов.
- Тяжёлое обучение — локально или на GPU; сабмит в сореву только после
  подтверждения на нашем протоколе валидации.
- **Не коммитить:** данные (`*.csv`, `*.parquet`, `*.zip`), артефакты
  моделей, `scratch/`, `runs/`.
- На Kaggle инференс без интернета: любой логгинг — no-op под флагом.
