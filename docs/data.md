# Данные

Документ описывает три слоя данных: официальный train/test Kaggle, публичный
пул генераций и фиксированные сплиты репозитория. Числа взяты из текущих
артефактов; если они расходятся с Kaggle dataset card, верьте карточке и
`dataset/`-манифесту.

## 1. Официальные данные соревнования

Источник: Kaggle-соревнование `name-that-llm`. Данные не входят в
репозиторий: правила соревнования запрещают их перепубликацию.

### `train.csv`

| колонка | тип | смысл |
|---|---|---|
| `id` | string | идентификатор пассажа |
| `prompt_id` | string | группа промпта; единица CV и бутстрапа |
| `text` | string | ответ модели |
| `model` | string | метка класса, одна из 18 моделей |

Размер — **2 699 строк**, **150 промптов**, **18 классов**. В 149 промптах
присутствуют все 18 моделей, в одном — 17 (у `claude-fable-5` нет одного
ответа). Поэтому «идеальный баланс 18 × 150» в данных не выполняется, и
метрика обязана это учитывать.

Длина текста: в среднем ≈115 слов, медиана ≈101, диапазон 36–274 слова.
Форматирование в основном очищено, но типографика (кавычки, тире, markdown)
осталась и несёт сигнал о модели.

### `test.csv`

Локально — **3 строки-заглушки** с колонками `id`, `text`. Реальный тест
открывается только в Kaggle rerun: около 4 000 пассажей на промптах, которых
нет в train. На один тестовый промпт приходится примерно **2 ответа**.

### Метка и метрика

18 классов — версии моделей шести семейств: `claude`, `gemini`, `glm`,
`gpt`, `kimi`, `qwen`. Точный список и порядок берутся из `sorted(train.model.unique())`;
жёстко зашивать порядок классов в код нельзя, потому что подсчёт OOF-
вероятностей должен выравниваться по `model.classes_`.

Метрика соревнования — balanced accuracy. Локально мы считаем две версии:

- **BA(18/prompt)** — по всем ответам промпта; используется в старых
  экспериментах на `splits/v2.json`;
- **BA(2/prompt)** — по двум случайно выбранным ответам на промпт; ближе к
  тесту и используется в новых протоколах.

Подробный разбор — в [`validation.md`](validation.md).

## 2. Публичный пул генераций

Kaggle dataset: **`morginalium/name-that-llm-clean-pool-v1`**
(статус: **опубликован**, версия 4; лицензия **CC BY-SA 4.0**).

Пул собран из публичных Kaggle-датасетов и kernel-выходов с генерациями
тех же 18 моделей. Каждый источник сохраняется в атрибуции; при слиянии
строки дедуплицируются по тексту и модели, а промпты — по каноническому
ключу.

### Объёмы

| слой | строк | промптов | что это |
|---|---:|---:|---|
| сырой пул | 190 588 | 44 041 `prompt_group` / 31 355 `prompt_canon` | всё, что собрано |
| keep_clean | **115 342** | **23 451** `prompt_canon` | после консервативного фильтра; 672 строки без canon |
| foldable clean | **114 670** | **23 451** `prompt_canon` | непустой canon, все строки с фолдом |
| официальный train | 2 699 | 150 `prompt_id` | данные соревнования |

`23 451` — число канонических промптов в чистом слое по манифесту датасета;
в сыром пуле `prompt_canon` может быть `NaN`/пустым, поэтому счётчики
`prompt_group` и `prompt_canon` не совпадают.

### Поля `pool_v1.parquet`

| колонка | смысл |
|---|---|
| `id` | идентификатор строки пула |
| `text` | сгенерированный пассаж |
| `model` | метка одной из 18 моделей |
| `prompt_group` | группа промпта внутри источника |
| `prompt_canon` | канонический промпт после слияния источников |
| `source_dataset`, `source_file` | откуда строка |
| `source_license` | лицензия источника |
| `also_in`, `n_sources` | в скольких источниках встречается текст |
| `max_cos_train`, `max_sim_train_prompt` | близость к train и его промптам |
| `style_score` | оценка стилевой выраженности |
| `flag_kb_proxy` | похоже на knowledge-base прокси, а не на генерацию |
| `flag_near_train_prompt` | промпт близок к train |
| `flag_train_prompt_regen` | регенерация train-промпта |
| `prompt_evidence`, `panel_labels` | сколько свидетельств/меток у промпта |

В чистом слое все `flag_*` равны `False`, `max_cos_train < 0.5`, тексты
непустые и длиннее 20 символов.

### Почему `prompt_group` ≠ `prompt_canon`

`prompt_group` — локальная группа источника. Один и тот же промпт в разных
датасетах имеет разные `prompt_group`, поэтому фолды по нему протекают:
модель видит тот же промпт в train и validation. `prompt_canon` — результат
кросс-источниковой дедупликации; фолды пула режутся только по нему.
Официальный train использует третий ключ — `prompt_id`, и он не совпадает
ни с одним из них.

### Доменный сдвиг

Пул — не тест и не train:

- другие промпты, другие шаблоны генерации, иногда другие температуры;
- часть строк — «прокси»-тексты и ответы, собранные чужими пайплайнами;
- метки моделей могут быть шумными (особенно у близких sibling-моделей);
- длина и форматирование отличаются от официальных.

Практический потолок переноса, который мы измерили: **0.36–0.40**
BA(2/prompt) на официальном holdout. Пул годится для предобучения энкодера
и для увеличения разнообразия, но не заменяет официальные 2 699 строк.

## 3. Сплиты репозитория

| файл | что внутри | как использовать |
|---|---|---|
| `splits/official_v1.json` | 150 промптов, 5 блоков по 30; блоки 0–3 dev, блок 4 sealed | каноническая валидация |
| `splits/pool_v1.parquet` | одна строка на `prompt_canon`: `fold`, `n_rows`, `n_clean`, `n_models`, `n_sources`, `source_top` | 5 фолдов пула по `prompt_canon` |
| `splits/labels.json` | 18 классов, 6 семейств, порядок индексов | канонический порядок меток |
| `splits/v2.json` | 30 locked holdout + 120 dev, 5 повторов (сиды 42–46) | исторические прогоны |
| `splits/v1.json` | старый holdout/dev | только история; в v1 были одинаковые псевдо-повторы |

Сборка и проверка датасета:

```bash
python scripts/build_dataset.py        # dataset/build/ + splits/
python scripts/validate_dataset.py     # проверки схемы, фолдов, хэшей
python scripts/upload_dataset.py --public
```

`build_dataset.py` детерминирован: при тех же входах получаются те же
`official_v1.json` и `pool_v1.parquet` (кроме timestamp в checks.json).
`validate_dataset.py` возвращает код 1 при ошибке, поэтому его можно
ставить в CI. `upload_dataset.py` публикует версию на Kaggle и проверяет
её после загрузки.

Правила:

1. `official_v1.json` — источник истины для новых экспериментов.
2. Sealed-блок нельзя смотреть до финального отчёта; никакого выбора
   гиперпараметров по нему.
3. `splits/v2.json` не удаляем: на нём получены числа в
   [`experiments.md`](experiments.md), и без него они не воспроизводятся.
4. Для пула используем `prompt_canon`, для официальных данных —
   `prompt_id`. Смешивать ключи в одном `GroupKFold` нельзя.

## 4. Загрузка в коде

```python
from ntl.data import load_train, load_test

train = load_train()   # NTL_DATA_DIR или /kaggle/input/...
test = load_test()
```

`NTL_DATA_DIR` переопределяет каталог с `train.csv`/`test.csv`. На Kaggle
путь по умолчанию — `/kaggle/input/competitions/name-that-llm`.

Пул в экспериментах читается напрямую:

```python
import pandas as pd
pool = pd.read_parquet("splits/pool_v1.parquet")
# старый сырой пул: research/pool/ntl_open_pool.parquet (не коммитится)
```
