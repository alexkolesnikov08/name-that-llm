# Roadmap

Цель — не догнать публичное плато 0.66 любой ценой, а получить собственный
воспроизводимый пайплайн с честной метрикой и понятным потолком. Roadmap
разбит на три этапа; каждый следующий открывается только после закрытия
предыдущего.

## Текущее состояние (2026-11-02)

- Собраны официальные данные, исторические сплиты `v1`/`v2`, пул 115k.
- Работает 7-view стек: **0.3917** dev BA(18), **0.356** LB.
- kNN-центрирование даёт **0.4712** dev, но **0.356** LB — не переносится.
- Char-BiGRU: **0.361** BA(2), Char-SVC на пуле: **0.347** BA(2).
- Чужой Gold Apex воспроизведён на **0.662** LB; в `main` его нет.
- Нет собственной модели, которая конкурирует с 0.66. Это осознанно
  зафиксировано, а не замаскировано.

## v1-protocol — данные и протокол

**Milestone:** `v1-protocol`.

Задачи:

1. **Данные и сплиты** (#22). Опубликовать
   `morginalium/name-that-llm-clean-pool-v1`, зафиксировать
   `splits/official_v1.json` (5 блоков × 30, sealed) и
   `splits/pool_v1.parquet` (5 фолдов по `prompt_canon`).
2. **OOF + BA(2)** (#23). Единый harness: OOF-вероятности по промптам,
   BA(2/prompt) с 25 draw-ами, парный bootstrap, отчёт по каждому фолду.

**Exit criteria:**

- `splits/official_v1.json` и `pool_v1.parquet` в репозитории, хэши
  зафиксированы;
- `PYTHONPATH=src pytest -q` зелёный на CI;
- BA(2)-harness даёт одинаковый результат при повторном запуске (сид
  фиксирован);
- ни один эксперимент не смотрит в sealed-блок.

**Зависимости:** нет. Это блокер для всех остальных этапов.

## v2-members — собственные модели

**Milestone:** `v2-members`.

Четыре независимых трека. Каждый обязан использовать протокол из v1 и
показывать BA(2) на development-блоках, а не BA(18).

### 1. Baselines (#24)

Повторить TF-IDF/LogReg, SVC, centroid и 7-view стек на `official_v1`.
Нужна честная нижняя граница и проверка, что harness не сломан.

### 2. LoRA 0.8B (#25)

Дообучить компактную модель 0.6–0.8B (LoRA/QLoRA) на официальном train.
Гипотеза: representation learning даст больше, чем ручные признаки, даже
на 2 699 строках, если правильно выбрать базовую модель и режим
заморозки. Обязательны: фиксированный сплит, early stopping только по
development, отдельный прогон без sealed.

### 3. RNN (#26)

Довести char-BiGRU: убрать регресс v2, проверить family-голову без
адверсария, подобрать длину/словарь на BA(2). Основной вопрос — перенос
с пула, а не качество на пуле.

### 4. Classic (#27)

Классические модели на пуле и официальном train: char-SVC, линейные
центроиды, kNN по TF-IDF. Нужны как контроль доменного сдвига и как
дешёвые члены ансамбля.

**Exit criteria:**

- у каждого трека есть отчёт: сплит, BA(2), CI, число параметров/время;
- хотя бы один трек значимо (парный bootstrap, CI > 0) бьёт baseline
  0.347 BA(2);
- нет утечек по `prompt_id`/`prompt_canon`;
- код и конфиг воспроизводятся одной командой.

**Зависимости:** v1-protocol.

## v3-ensemble — ансамбль и мета

**Milestone:** `v3-ensemble`.

1. **Meta** (#28). Стекинг OOF-вероятностей членов v2: LogReg/lightGBM,
   калибровка (temperature/isotonic), веса по фолдам. Сравнение с лучшим
   одиночным членом, а не с пустым baseline.
2. **Assignment/структура.** Hungarian/Sinkhorn и ограничение «одна модель
   на промпт» — только если парный CI положительный на development.
   Исторически эти трюки теряли LB, поэтому по умолчанию выключены.
3. **Инфраструктура** (#29). CI, реестр экспериментов, валидатор сабмита
   и тег релиза.

**Exit criteria:**

- ансамбль бьёт лучшего члена на **≥0.015** BA(2) с парным CI > 0;
- LB-сабмит подтверждает направление (не обязательно абсолют);
- решение задокументировано в `docs/experiments.md`, включая провалы;
- тег/релиз с воспроизводимым сабмитом.

**Зависимости:** v2-members.

## v1-protocol → v2 → v3: что не делаем

- Не оптимизируем LB на public-части: private — 60%, переподгонка на public
  бесполезна.
- Не выдаём Gold Apex за свою модель и не строим roadmap вокруг его скора.
- Не добавляем признаки, посчитанные на тесте, без отдельного
  transductive-протокола.
- Не закрываем issue без вердикта: подтверждено / опровергнуто / шум.

## Риски

| риск | что делаем |
|---|---|
| Мало данных (150 промптов) | групповой CV, BA(2), парный bootstrap |
| Domain shift пула | отдельный holdout по `prompt_canon`, не смешиваем с official |
| Утечка промптов | проверки пересечений и near-duplicate до прогона |
| Переподгонка на sealed | один финальный отчёт, без итераций |
| Чужой код в main | Gold Apex только в теге, атрибуция в `kaggle/gold_apex/` |
| Нет GPU | CPU-ветки для baseline/stack, RNN/LoRA — отдельно |
